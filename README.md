# BU Catalog V9 — локації та персональний доступ

## Що виправлено
- Місто та адреса зберігаються сервером; після збереження сайт використовує підтверджені дані сервера.
- Поле міста дозволяє обрати підказку з наданого списку 29 локацій АБО ввести довільну назву.
- Адреса — довільний текст. При виборі іншого міста стандартна чернігівська адреса очищується.
- Фільтр локацій працює за містом/локацією, а картка показує і місто, і адресу.
- Сортування: лише «Спочатку з фото».
- При додаванні, редагуванні й завантаженні фото сайт чекає явного підтвердження Apps Script.
- Якщо у Google стара версія, вхід показує зрозуміле повідомлення про необхідність оновлення.

## Чому Київ показувався як Чернігів
Перевірений чинний API повертав тестову позицію 12414 без полів city/address.
HTML уже був новий, але введення в дію Apps Script лишалося старим.
Оновлення лише index.html не змінює серверну логіку збереження.

## Встановлення — обов’язково оновити ОБИДВІ частини

### 1. Google Apps Script
1. Відкрийте ЧИННИЙ проєкт Apps Script, який використовується вашим каталогом.
2. Збережіть копію старого коду. Замініть його вмістом Code.gs з цього архіву.
3. Додайте два файли скрипту: Auth і PasswordCrypto. Вставте в них вміст Auth.gs і PasswordCrypto.gs відповідно.
   У проєкті не повинно залишатися інших старих doGet/doPost або CONFIG: інакше буде дублювання.
4. Перевірте SPREADSHEET_ID і DRIVE_FOLDER_ID у Code.gs. У файлі залишені ID вашого каталогу.
5. Налаштування проєкту → Властивості скрипту → Додати властивість:
   Назва: INITIAL_ADMIN_PASSWORD
   Значення: ваш власний пароль адміністратора, щонайменше 10 символів.
   Не використовуйте пароль корпоративної пошти. Не додавайте пароль у HTML чи GitHub.
6. Виберіть функцію setupV9 і натисніть «Запустити». Погодьте запитані доступи Google.
   Функція створить приватну таблицю «БУ Каталог — Користувачі та журнал» і користувача admin.
   Після успішного створення одноразова властивість INITIAL_ADMIN_PASSWORD автоматично видаляється.
   setupV9 можна повторити: вона не змінює пароль уже створеного admin.
7. Ввести в дію → Керувати введеннями в дію → Олівець → Нова версія → Ввести в дію.
   Виконується від вашого імені; вебзастосунок доступний для виклику сайтом.
   ОНОВІТЬ чинне введення в дію, щоб URL /exec не змінився.
   Якщо URL змінився, оновіть API_URL в index.html.

### 2. GitHub
1. Замініть index.html в репозиторії файлом із цього архіву.
2. Дочекайтеся завершення публікації GitHub Pages.
3. Відкрийте сторінку з повним оновленням Ctrl+F5.
4. Натисніть «Увійти»: логін admin, пароль — заданий вами на кроці 5.

## Користувачі
Після входу адміністратора з’явиться кнопка «Користувачі».
Адміністратор вводить ПІБ, логін, пароль, роль і статус доступу.
Можна змінити пароль, роль, логін або заблокувати користувача.
При редагуванні порожнє поле пароля зберігає старий пароль.
Зміна даних доступу відкликає попередні сеанси цього користувача.
Себе не можна заблокувати або позбавити прав адміністратора через цю форму.

Ролі:
- Перегляд — не дозволяє змінювати каталог.
- Додавання фото — лише фото до наявних позицій; без видалення фото, зміни даних і створення позицій.
- Редактор — створення й редагування позицій, фото; без архівування та відновлення позицій.
- Адміністратор — усі дії, користувачі та журнал.

Кнопка «Журнал змін» показує останні 100 дій. Повна історія збережена на приватному аркуші History.
Фіксуються користувач, логін, дія, артикул, час і дані до/після зміни.
Окремий пароль видалення замінено перевіркою персональної ролі admin та підтвердженням артикулу.
Паролі хешуються PBKDF2-HMAC-SHA256 (600000 ітерацій, окрема сіль та серверний секрет).
Відновити старий пароль неможливо — адміністратор задає новий.
Паролі та токени не пишуться в журнал і не передаються в URL.
Сеанс діє 8 годин; в браузері зберігається токен сеансу, а не пароль.
Перший вхід/створення користувача може зайняти кілька секунд через обчислення хеша.

## Важливо про видимість
Збережено поточний режим перегляду каталогу без входу.
Вхід захищає операції зміни, права перевіряються на сервері, а не лише кнопками.
У HTML є резервні дані, а основна таблиця має публічне читання, як у попередній версії.
Users і History — ОКРЕМА приватна таблиця: не публікуйте її й не надавайте загального доступу.
Паролі з нової форми не створюються безпосередньо ручним введенням у таблицю: користуйтеся кнопкою «Користувачі».
Для повністю закритого перегляду потрібно окремо змінити читання каталогу і доступи до Google Sheet/фото.

## Збереження локацій
Catalog: A:G — як раніше, H — City, I — Address.
Archive: H — DeletedAt (без змін), I — City, J — Address.
setupV9 заповнює порожні локації старих позицій Черніговом і стандартною адресою.
Вже введені міста не замінюються на Чернігів.
Перевірте тестову позицію 12414: якщо старий сервер не зберіг Київ, відкрийте її і збережіть місто заново.

## Перевірка після встановлення
- Увійдіть як admin.
- Створіть тестову позицію: Київ, власна адреса. Перезавантажте сторінку й відкрийте картку.
- Створіть позицію з містом, якого немає у списку. Перевірте збереження й фільтр.
- Додайте користувача ролі «Додавання фото», перевірте його доступ.
- Перевірте журнал і відновлення з архіву.

Перевірено локально: синтаксис, взаємодія HTML з відповідями API у моделі DOM, збереження міста/адреси,
сумісність архіву V6, хешування паролів, ролі, блокування сеансів і журнал.
Це файли для встановлення. Чинний сайт і Apps Script автоматично не змінювалися.
